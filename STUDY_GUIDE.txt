1. كيف يبدأ الهيكل؟ (App Execution Lifecycle)
--------------------------------------------------------------------------------
إذا سألك الإنستراكتور: "التطبيق بيبدأ إزاي والملفات مربوطة ببعض إزاي؟"

1) index.html:
   - هي صفحة الـ HTML الوحيدة في التطبيق (Single Page Application - SPA).
   - تحتوي على <div id="root"></div> وسطر استدعاء ملف الجافاسكريبت:
     <script type="module" src="/src/main.jsx"></script>

2) src/main.jsx:
   - نقطة الانطلاق في React (Entry Point).
   - بتمسك العنصر document.getElementById('root') وبترندر جواه المكون الأساسي <App /> عبر ReactDOM.

3) src/App.jsx:
   - هو المكون الأب الرئيسي (Parent Component).
   - فيه بيتم تخزين الـ State الأساسي (قائمة الطلاب، بيانات الفورم، البحث، التعديل).
   - بيستدعي المكونات الفرعية (StudentForm و StudentCard) وبيمرر ليها البيانات كـ Props.

4) src/data/studentsData.js:
   - ملف خارجي فيه مصفوفة طلاب أولية (initialStudents) علشان التطبيق أول ما يفتح ميبقاش فاضي.

5) src/components/:
   - StudentForm.jsx: فورم الإضافة والتعديل مع التحقق من صحة المدخلات.
   - StudentCard.jsx: كارت عرض بيانات الطالب مع أزرار التعديل والحذف.


--------------------------------------------------------------------------------
2. جميع الـ Hooks المستخدمة (useState & useEffect)
--------------------------------------------------------------------------------

أولاً: useState (إدارة الحالة):
--------------------------------
1. students:
   - القيمة: مصفوفة تحتوي على كائنات الطلاب.
   - الهدف: عرض قائمة الطلاب وتحديثها عند الإضافة، التعديل، أو الحذف.

2. name, age, email:
   - القيمة: نصوص (Strings) فارغة مبدئياً.
   - الهدف: ربط حقول الإدخال في الفورم بحالة React (Controlled Inputs).

3. editingId:
   - القيمة: null (افتراضياً)، أو رقم id الطالب الجاري تعديله.
   - الهدف: معرفة هل نحن في وضع "إضافة طالب جديد" أم "تعديل طالب موجود".

4. error:
   - القيمة: نص رسالة الخطأ أو نص فارغ.
   - الهدف: إظهار تنبيه للمستخدم في حالة عدم ملء الحقول أو إدخال بيانات غير صحيحة.

5. searchQuery:
   - القيمة: نص البحث المكتوب.
   - الهدف: فلترة الطلاب لحظياً بالاسم أو البريد الإلكتروني.


ثانياً: useEffect (التأثيرات الجانبية):
---------------------------------------
الكود:
useEffect(() => {
  localStorage.setItem("students_data", JSON.stringify(students));
  document.title = `(${students.length}) Students — Registry Studio`;
}, [students]);

- سؤال متوقع: "ليه حطينا [students] في الـ Dependency Array؟"
  الإجابة: علشان التأثير ميتنفذش إلا لما مصفوفة students تتغير فقط.
- ماذا يفعل؟
  1. يحفظ قائمة الطلاب في localStorage حتى لا تضيع البيانات عند تحديث الصفحة (Refresh).
  2. يحدث عنوان التاب في المتصفح تلقائياً بعدد الطلاب الحاليين.


--------------------------------------------------------------------------------
3. شرح جميع الدوال والوظائف (Functions Breakdown)
--------------------------------------------------------------------------------

1) دالة handleSubmit(e):
   - e.preventDefault(): يمنع إعادة تحميل الصفحة الافتراضي عند إرسال الفورم.
   - التحقق (Validation):
     * !name.trim() || !age || !email.trim() -> التأكد من ملء جميع الحقول.
     * Number(age) <= 0 || isNaN(Number(age)) -> التأكد أن السن رقم موجب أكبر من 0.
     * !email.includes("@") -> التأكد أن الإيميل يحتوي على علامة @.
   - التمييز بين الإضافة والتعديل:
     * إذا كان editingId !== null: نستخدم students.map() لتعديل الطالب الذي يتطابق id الخاص به، ونرجع باقي الطلاب كما هم.
     * إذا كان editingId === null: ننشئ كائناً جديداً بـ Date.now() ونضيفه للمصفوفة عبر [...students, newStudent].
   - تفريغ الحقول ومسح رسالة الخطأ بعد الانتهاء بنجاح.

2) دالة handleDelete(id):
   - تحذف الطالب من المصفوفة باستخدام:
     students.filter((student) => student.id !== id)
   - إذا كان الطالب المحذوف هو المعروض حالياً في الفورم، تلغي وضع التعديل فوراً.

3) دالة handleEdit(student):
   - تضع بيانات الطالب المختار في الحقول (setName, setAge, setEmail).
   - تضع id الطالب في editingId لتحويل الفورم إلى وضع التعديل.

4) دالة handleCancelEdit():
   - تلغي وضع التعديل (setEditingId(null)) وتفرغ الحقول.

5) فلترة البحث (filteredStudents):
   - students.filter(...) للبحث في الاسم والإيميل عبر toLowerCase() و includes().


--------------------------------------------------------------------------------
4. أهم أسئلة الإنستراكتور وإجاباتها النموذجية
--------------------------------------------------------------------------------

س1: ليه بنكتب [...students, newStudent] ومبنعملش students.push(newStudent)؟
الإجابة:
في React، الـ State يعتبر غير قابل للتعديل المباشر (Immutable).
دالة push تعدل في نفس مكان المصفوفة في الذاكرة ولا تغير الـ Reference، فـ React لن تلاحظ التغيير ولن تعيد رسم الصفحة (Re-render).
أما الـ Spread Operator [...] ينشئ مصفوفة جديدة تماماً، فيجبر React على تحديث الواجهة.

س2: ما هو الـ Controlled Component؟
الإجابة:
هو حقل إدخال (input) تكون قيمته مخزنة في الـ State وتتحكم فيها React بالكامل عبر value={name} و onChange={(e) => setName(e.target.value)}.

س3: ما فائدة e.preventDefault() في الفورم؟
الإجابة:
النموذج في HTML يعيد تحميل الصفحة افتراضياً عند الـ Submit، واستخدام e.preventDefault() يمنع هذا السلوك لنعمل كتطبيق صفحة واحدة (SPA).

س4: كيف قمت بتنفيذ ميزة التعديل (Update) برمجياً؟
الإجابة:
1. عند الضغط على Edit نأخذ بيانات الطالب ونملأ بها الـ inputs ونحفظ id الطالب في editingId.
2. عند الضغط على Save نفحص هل editingId موجود.
3. نستخدم دالة map؛ إذا كان student.id === editingId نرجع الكائن بالبيانات الجديدة، وإلا نرجع الطالب القديم دون تغيير.
4. نعيد editingId إلى null ونفرغ الحقول.

س5: كيف تعمل دالة الحذف (Delete)؟
الإجابة:
باستخدام دالة filter التي تمر على عناصر مصفوفة الطلاب وترجع مصفوفة جديدة تحتوي فقط على الطلاب الذين لا يساوي الـ id الخاص بهم الـ id المطلوب حذفه.
